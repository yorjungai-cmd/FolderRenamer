# Folder File Renamer — Claude Context

## What this project is

Windows desktop app (Python 3.11+ / PyQt6) that batch-translates Japanese filenames to English via DeepL or an OpenRouter LLM. Key workflow: add files → translate → preview per-file → approve → apply renames. Every rename session is saved and can be reverted.

## Key architecture rules

- **Core is Qt-free.** `core/` and `api/` have zero PyQt6 imports — they are pure Python and fully unit-tested. QThread workers in `workers/` bridge async work to the UI via signals.
- **Workers communicate only via signals.** Never call UI methods directly from a worker thread.
- **Config lives in `%APPDATA%\FolderFileRenamer\config.json`.** Load with `AppConfig.load()`, save with `config.save()`. New fields go on `AppConfig` (or `SanitizationConfig`) as dataclass fields with defaults — existing saved configs will pick them up gracefully.
- **Sessions live in `%APPDATA%\FolderFileRenamer\sessions\`.** Auto-pruned to 50. `core/session_store.py` owns all session I/O.

## Filename length handling

Two layers, applied in order in `main_window._on_translation_result`:

1. **Soft limit** — `config.max_filename_chars` (0 = off). Trims the stem in Python chars.
2. **Hard limit** — `safe_filename_length(stem, ext, max_bytes=255)` in `rename_engine.py`. Trims by UTF-8 bytes.

Visual feedback in `PreviewPanel.set_translated`: yellow ≥ 200 chars, red ≥ 255 chars.

## Building

```bash
pyinstaller folder_file_renamer.spec --clean

```


## Patterns to follow

- Add UI controls in `_build_toolbar()` / `_build_ui()`, wire signals in `_connect_signals()`, handle in `_on_*` methods.
- New settings: add field to `AppConfig` (with default), add widget to `SettingsDialog._san_tab()` or `_filt_tab()`, load in `_load()`, save in `_save()`.
- New core logic: write test first in `tests/`, implement in `core/` with no Qt import.
- QSS object names use kebab-case (e.g. `setObjectName("btn-danger")`).
